# The composition contract

Slides are HTML rendered headlessly at the target size. Not Canva, not a design tool.
The point is that copy lives in one file, so a wording change is a one-line edit and a
re-render, not a manual redraw of twenty-nine images.

## Pipeline

 manifest.tsv key<TAB>photo path. One line per usable photograph.
 placement.json generated by place.py. Never hand-edited.
 css.txt the shared stylesheet. Brand tokens sampled from the live site.
 build.py the decks. All copy lives here. Writes out/*.html
 shoot.py Playwright, renders out/*.html to PNG at the target size
 qa_gate.py fails the build on banned claims and structural faults
 previews.py contact sheets, profile-row mockup, thumbnail legibility test

Run order: `place` (only after adding photos) → `build` → `shoot` → `qa_gate` → `previews`.

**`build.py` clears the render directory on every run.** Renders are disposable; the
source is the truth. Do not put anything precious in there.

## Slide sizes

| Surface | Size | Notes |
|---|---|---|
| Feed carousel | 1080 x 1350, 4:5 | no crop in feed |
| Story | 1080 x 1920, 9:16 | keep copy clear of the top and bottom 250px for UI |
| Profile grid, desktop | 279 x 372, 3:4 | centre crop of the 4:5 |
| Profile grid, mobile | ~130 x 173, 3:4 | the real legibility test for a cover |

Nothing load-bearing goes in the outer 12% of the width.

## Slide types

**cover**, display title, one hard specific under it, no slide number.
**proof**, the review card. See below.
**content**, one fact in the display face, connective tissue beneath.
**cta**, the close. One ask. See the CTA rules in SKILL.md.

## The scrim

Photo slides carry a gradient so copy stays legible without flattening the picture.

 copy at bottom transparent at top, ~0.97 opaque at the bottom, steep from ~64%
 copy at top the mirror
 copy at top of a cover deeper: hold density to ~56% before releasing

That last one is not optional. A tall title block at the top runs to roughly 45% of the
frame, and the plain mirrored gradient has already faded out by then, so the footer lands
on unprotected photo and disappears. Always check the footer, never the headline.

## The review card

A rounded card floating over the lower edge of a photograph. Reads like a screenshot of a
real review but is typeset in the brand faces at full resolution.

 .rcard cream ground, 34px radius, 50px/54px padding, 0 34px 80px rgba(0,0,0,.55)
 .ravatar 78px circle, brand navy, the reviewer's initial in the display face
 .rname sans, 600 weight
 .rstars five filled stars, amber #E0A337
 .rgoogle "GOOGLE" top right, small, letterspaced, muted
 .rtext the review verbatim, display face, 1.36 line height

The photograph runs deep enough that the card overlaps its lower edge. Size the photo band
by quote length so nothing overflows: longer quote, shorter band.

Do not use an actual screenshot. It brings the platform's own UI, its font, whatever
resolution the phone captured, and light-mode chrome that fights a dark set.

## Per-slide overrides

`place.py` is a good default and it is wrong in one specific case: when the subject
occupies the empty-looking region. Fireworks that need headroom. Faces high against a
plain wall. A lone figure in negative space. The score sees flat pixels and puts type
there, straight over the thing the photograph is about.

Set `pos="top"` or `pos="bottom"` on that slide. The override lives in the source, so
re-running placement can never move it back.

Both overrides in the BALIVIP set were subjects sitting high in the frame. If this keeps
recurring, add face detection: faces above the midline force copy to the bottom.
