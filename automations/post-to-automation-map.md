## Rules

1. **One post, one destination.** Never two asks.
2. **Nothing publishes without a row here.** If it is not in the table, the
   destination has not been checked.
3. **Test from a second account** before the post goes live, every time.
4. **Tag every contact with the post name.** Without it you cannot tell which post
   produced an enquiry, and the whole analytics folder is guesswork.

## The pin 1 problem, and why it matters

Pin 1's caption promises "**No form, no call.**" So its keyword must be answered
**in the DM**. If the automation replies with a link to a long application form, the
post breaks its own promise on the slide, and that is worse than not running the
automation at all.

Pin 1 = ManyChat answers in the DM.
Pins 2 and 3 = link in bio is fine, because neither promises no form.

## Link in bio

Use one link tool, and put UTM parameters on every destination so traffic is
traceable:

```
/apply?utm_source=instagram&utm_medium=social&utm_campaign=pin3-dates
```

Without UTMs every click arrives with no attribution and nobody can tell which post
is working.
